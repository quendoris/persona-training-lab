# Persona Training Lab — Codex Handoff

## 1. Роль Codex
Codex — инженерный исполнительный слой. Он помогает быстро применять изменения в коде, но не принимает продуктовые и визуальные решения самостоятельно.

## 2. Кто принимает решения
Авторы проекта принимают решения по:
- продуктовой логике
- архитектуре
- визуальному направлению
- тому, что считается зафиксированной версией

## 3. Что Codex должен считать источником правды
В первую очередь:
1. текущий git state
2. `docs/context/*`
3. актуальные assets и иконки
4. README и встроенные screen rules

## 4. Главное рабочее правило
Применили → Проверили → Понравилось авторам → Зафиксировали как новую правду проекта.

Codex не должен:
- самовольно перепридумывать уже принятые интерфейсные решения
- возвращать старые паттерны, если они уже сознательно заменены
- вшивать hardcode-цвета туда, где решение должно жить через theme manager

## 5. Что важно помнить о проекте
- это не просто scaffold, а исследовательская рабочая станция
- интерфейс должен быть серьёзным, но живым
- project context важнее случайной догадки по одному файлу
- git patch/diff — нормальный основной способ обмена изменениями

## 6. Что делать, если контекст неполный
Если не хватает контекста:
- не изобретать новые правила
- спросить только там, где это реально необходимо
- опираться на текущую утверждённую версию кода
