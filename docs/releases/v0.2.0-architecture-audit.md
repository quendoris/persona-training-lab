# Persona Training Lab v0.2.0 — architecture completion audit

## Purpose

`v0.2.0` closes the large desktop-architecture refactor. The milestone is not
complete merely because the current tests pass or the interface looks stable.
It is complete only when the production system matches its intended ownership,
lifecycle, transaction, localization and observability architecture without
historical compatibility layers silently participating in the runtime graph.

This audit is intentionally stricter than ordinary regression testing. Its job
is to detect code that still works for accidental historical reasons after the
refactor.

## Blocking architecture audit

The audit is performed after the refactor and release localization are complete.
Every item below is blocking for declaring the desktop architecture finished.

### Ownership and dependency graph

- [ ] Every production responsibility has one explicit owner.
- [ ] Public screen imports point directly to production implementations, not to
      compatibility modules.
- [ ] Compatibility modules are re-exports only and do not own runtime state,
      lifecycle hooks or policy decisions.
- [ ] QWidget inheritance is used only for genuine Qt/widget specialization, not
      as a transport for application policy, persistence or transaction state.
- [ ] Pure policies, planners and state machines can be tested without creating
      `QApplication`.
- [ ] Dependency direction follows domain/application/infrastructure/UI
      boundaries; no production dependency relies on a test or compatibility
      path.
- [ ] Constructors do not require post-construction mutation to finish dependency
      injection.

### Threading and lifecycle

- [ ] GUI-thread code performs no hidden database, filesystem or model-service
      reads that belong to workers or application services.
- [ ] Worker-owned resources are created, used and closed on their owning thread.
- [ ] No refresh or operation can overlap unless concurrency is explicitly part
      of its contract.
- [ ] Generation/revision guards reject stale asynchronous results.
- [ ] Timers activate and deactivate with the owning UI lifecycle.
- [ ] Application shutdown is bounded, observable and does not use forced thread
      termination.
- [ ] Partial construction failure closes already-created background resources.
- [ ] Repeated navigation and screen destruction leave no orphan QThreads,
      timers, leases or signal connections.

### Transactions and persistence

- [ ] Multi-resource destructive operations have an explicit prepare/commit
      boundary.
- [ ] Filesystem state uses atomic replacement where partial writes would violate
      invariants.
- [ ] In-memory state never reports rollback after an irreversible persistence
      commit has already occurred.
- [ ] SQLite/resource-link mutations that form one invariant execute in one
      transaction.
- [ ] Failed operations restore an exact technical snapshot instead of creating
      misleading user undo/redo history.
- [ ] Boolean or status-returning finalization APIs cannot fail silently.
- [ ] Corrupted or unreadable persisted state fails explicitly instead of being
      interpreted as an empty valid state.
- [ ] Existing valid older schemas migrate without destructive reset.

### Error and observability boundaries

- [ ] Every caught background exception either becomes a typed result or reaches
      the application error reporter.
- [ ] Post-commit failures are distinguishable from pre-commit failures.
- [ ] Last-good UI state is retained when a refresh fails.
- [ ] Error reports contain enough semantic context to reproduce the failing
      operation without exposing private payloads unnecessarily.
- [ ] Repeated Qt/application warnings are bounded or deduplicated.
- [ ] The user interface never displays a state known to contradict committed
      persistence.

### Interaction architecture

- [ ] Keyboard/mouse gesture semantics are separated from Qt event transport.
- [ ] Shortcut ownership and conflict routing have deterministic policy tests.
- [ ] Layout/zoom/scroll calculations that do not require Qt are pure and
      deterministic.
- [ ] History/undo behaviour is not dependent on accidental QWidget MRO order.
- [ ] Rapid input, layout switching and modifier-release edge cases have explicit
      regression contracts.
- [ ] Visual canvas state remains stable across content-only refreshes when the
      topology and visual footprint are unchanged.

### Localization architecture

- [ ] All production UI text is semantic-catalog driven.
- [ ] `tools/i18n_audit.py --strict-ui-literals` reports zero production UI
      literals.
- [ ] RU and EN expose the same semantic key set and formatting signatures.
- [ ] Live locale switching preserves selection, drafts, active operations and
      background-worker ownership.
- [ ] Compatibility/archaeological modules are either excluded from production
      UI-literal accounting or localized if they remain executable.

### Test and release architecture

- [ ] The complete refactored desktop foundation is represented explicitly in
      the blocking quick gate.
- [ ] Full pytest passes under `QT_QPA_PLATFORM=offscreen`.
- [ ] Compileall and Ruff pass over `src`, `tests` and `tools`.
- [ ] Mypy status is reviewed and remaining exceptions are intentional and
      documented.
- [ ] A clean-profile and an existing-profile smoke run both pass.
- [ ] Repeated navigation, active-operation shutdown and failure-injection smoke
      runs pass without uncontrolled stderr output.
- [ ] Codebase statistics are recorded for the audited commit.

## Reproducible visual audit bundle

After refactoring and release localization are complete, the repository must
contain a deterministic Qt visual-audit harness. It is not an OS-level screenshot
script tied to one compositor. The harness owns the application process/window
through Qt so it remains usable under Wayland, X11 and offscreen-compatible CI
where supported.

### Required behaviour

- [ ] Launch or attach to the Persona Training Lab application in a dedicated
      visual-audit mode.
- [ ] Locate the main top-level Qt window deterministically.
- [ ] Enumerate supported workspace routes from the application's navigation
      registry rather than a duplicated hard-coded list where possible.
- [ ] Visit every visible sidebar workspace in a stable order.
- [ ] Wait for route activation, queued UI work and known background refreshes to
      reach a stable capture point.
- [ ] Capture the application window itself through Qt (`QWidget.grab()` or the
      equivalent stable window capture), avoiding compositor-specific screen
      scraping as the primary path.
- [ ] Capture every release locale, initially `ru-RU` and `en-US`.
- [ ] Use a documented canonical window size, UI scale, theme and accent for the
      baseline set.
- [ ] Record route key, locale, window size, scale, theme, commit SHA and capture
      timestamp alongside each PNG.
- [ ] Preserve failures explicitly: a route that cannot stabilize or capture must
      make the harness fail instead of silently omitting its image.
- [ ] Package PNG files, a JSON manifest and a short text summary into one ZIP
      artifact.

### Visual review acceptance

The generated bundle is reviewed as a complete physical-interface snapshot, not
as isolated hero screenshots. Review covers at least:

- [ ] clipping, overlap and accidental horizontal scrollbars;
- [ ] inconsistent padding, card geometry and alignment;
- [ ] unreadable status, focus or disabled states;
- [ ] Russian/English size regressions;
- [ ] stale placeholder/loading states that survive capture stabilization;
- [ ] inconsistent typography or semantic emphasis between workspaces;
- [ ] lineage canvas framing and details-panel balance;
- [ ] docks/panels occupying unintended geometry;
- [ ] controls that are technically present but visually misleading or hidden;
- [ ] visual inconsistencies that automated layout tests do not express.

The reviewed ZIP and audit notes are release artifacts for the audited commit.
They provide a reproducible way for a human or multimodal reviewer to inspect the
entire desktop shell after structural and localization changes.

## Completion rule

The refactor is considered complete only when the blocking architecture audit,
full localization audit, automated quality gates, smoke lifecycle checks and the
visual audit bundle all refer to the same commit (or to a strictly documented
successor containing audit-only fixes).

Passing tests alone is necessary but not sufficient. The goal of `v0.2.0` is a
desktop architecture whose runtime behaviour follows the intended design rather
than surviving because of historical inheritance, incidental initialization
order or compatibility residue.
