# Persona Training Lab v0.1.0 — release checklist

## Purpose

The first public milestone fixes the current desktop laboratory as a coherent,
usable research workstation before the large architectural refactor.

The release is not presented as a finished scientific method or a production
training service. It is a stable experimental platform with working datasets,
training configuration, model-version lineage, portraits, comparisons,
resource-safety rules, live navigation, key bindings and operational feedback.

## Release branch

- Branch: `release/v0.1.0-polish`
- Base commit: `63f66e4660a20edfb97438bdf388a900de7a5f86`
- Package version: `0.1.0`

## Exit criteria

The release is ready only when every mandatory item below is complete.

### Functional polish

- [ ] Every sidebar tab opens and remains usable after repeated navigation.
- [ ] Dashboard stages route to the correct workspace and guidance target.
- [ ] Global tab shortcuts work and update after remapping.
- [ ] Direct key-binding capture, cancellation and conflict drafts remain stable.
- [ ] Lineage selection, branch creation, comparison and portrait routing work.
- [ ] Active runtime resources prevent unsafe lineage deletion.
- [ ] Activity, Problems, Inspector and active-process panels show real data.
- [ ] Recoverable errors stop only the affected operation and are logged once.
- [ ] Application shutdown releases workers, timers and runtime leases cleanly.

### Visual polish

- [ ] Brand card is compact; the Panels control renders fully above neighbours.
- [ ] Sidebar remains readable at supported UI scales and window sizes.
- [ ] No clipped labels, accidental horizontal scrollbars or overlapping cards.
- [ ] Every theme and accent keeps readable contrast and visible focus states.
- [ ] Lineage canvas zoom keeps the pointer anchor during rapid wheel input.
- [ ] Lineage canvas pan, drag, zoom and workspace growth do not jump or drift.
- [ ] Floating and docked panels preserve layout without stale geometry.
- [ ] Empty, loading, success, blocked and error states are visually distinct.

### Data and safety

- [ ] Existing databases migrate without deletion or manual schema repair.
- [ ] Missing artifacts are reported without substituting another model version.
- [ ] Interrupted operations become abandoned and release their resources.
- [ ] Destructive actions require confirmation and preserve protected history.
- [ ] Physical model artifacts are not deleted before quarantine/GC exists.
- [ ] Logs rotate and repeated Qt/application warnings are deduplicated.

### Tests and quality gate

- [ ] `python -m compileall src tests tools` succeeds.
- [ ] Full pytest suite passes with `QT_QPA_PLATFORM=offscreen`.
- [ ] Ruff check passes.
- [ ] Mypy result is recorded; known failures are documented explicitly.
- [ ] A clean-profile smoke launch succeeds.
- [ ] Existing-profile smoke launch succeeds.
- [ ] Repeated navigation smoke test succeeds.
- [ ] Key-binding conflict/leave-guard smoke test succeeds.
- [ ] Fast lineage zoom/pan smoke test succeeds.
- [ ] Runtime-operation conflict and recovery smoke tests succeed.
- [ ] stderr contains no uncontrolled repeated warnings.

### Documentation

- [ ] README explains what the laboratory is and is not.
- [ ] Installation instructions cover base, inference and training extras.
- [ ] Quickstart describes one complete lightweight workflow.
- [ ] Architecture overview matches the current code, not the future refactor.
- [ ] Runtime safety and error policy are linked from the README.
- [ ] Known limitations are explicit and honest.
- [ ] Screenshot set covers Dashboard, Agents, Training, Tests and Analysis.
- [ ] CHANGELOG contains the v0.1.0 feature and limitation summary.

### Packaging and release

- [ ] Build wheel and source distribution successfully.
- [ ] Install the built wheel into a clean virtual environment.
- [ ] Launch the installed package without the repository on `PYTHONPATH`.
- [ ] Create signed or annotated tag `v0.1.0`.
- [ ] Publish release notes and checksums for attached artifacts.
- [ ] Record codebase statistics for the release commit.

## Release test commands

```bash
uv sync --extra dev
uv run python -m compileall src tests tools
QT_QPA_PLATFORM=offscreen uv run pytest -q
uv run ruff check src tests tools
uv run mypy src
uv build
```

Mypy is initially informational unless the release branch explicitly promotes it
to a blocking gate. Any accepted failures must be listed in the release notes.

## Manual acceptance route

1. Start from a clean temporary profile and database.
2. Visit every workspace through both mouse navigation and `Alt+<key>`.
3. Create or select a profile and dataset.
4. Inspect training configuration without starting an expensive real run.
5. Open Agents, create a local branch and inspect its action matrix.
6. Create and resolve a temporary key-binding conflict.
7. Exercise rapid zoom, pan and node movement on the lineage canvas.
8. Open Activity, Problems and Inspector and verify live context.
9. Close the application while no operation is active.
10. Repeat shutdown with a controlled fake operation once the smoke harness exists.

## Known non-goals for v0.1.0

- Full scientific validation of the psychological methodology.
- Final mathematical model of personality dynamics.
- Long-running real-model stress validation.
- Distributed workers or remote orchestration.
- Physical artifact deletion and garbage collection.
- Final refactored lineage architecture.
- Interaction experiments between two autonomous agents.

## Planned release sequence

- `v0.1.0` — first coherent desktop laboratory.
- `v0.2.0` — post-refactor architecture and unified quality gate.
- `v0.3.0` — reproducible real-model end-to-end experiments.
- `v0.4.0` — mathematical and psychological measurement framework.
- `v1.0.0` — defended, documented and reproducible research platform.

The version numbers describe stable project milestones, not claims that the
scientific questions are solved.

## Project-page outline

The public page should remain understandable without exposing private research
materials or model artifacts.

1. Hero: name, brain-circuit mark and one-sentence purpose.
2. What it does: datasets, training, lineage, portraits, comparisons and safety.
3. Why it exists: reproducible study of stable artificial-agent personality.
4. Screenshots or a short restrained interface video.
5. Architecture diagram from input data to versioned model and measurements.
6. Release downloads, requirements and quickstart.
7. Research status, limitations and ethics.
8. Roadmap and release history.
9. Documentation and source links.

The page should look like the laboratory itself: dark, precise and restrained,
with the accent colour used for state and navigation rather than decoration.
